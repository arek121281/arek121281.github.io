Czym jest JCL i ARC?

Podstawy języka sterowania zadaniami

📘 Definicja JCL

JCL (Job Control Language) to język używany w systemach mainframe IBM do opisywania zadań (jobów) wykonywanych przez system operacyjny z/OS. Pozwala określić:

  • Jakie programy mają być uruchomione
  • Jakie zasoby (pliki, urządzenia) są potrzebne
  • Jakie parametry sterują wykonaniem

💡 Co to jest ARC?

ARC (Advanced Resource Control) to narzędzie lub warstwa zarządzająca zasobami w środowisku mainframe, która często rozszerza możliwości JCL o dodatkowe zmienne, makra i mechanizmy kontroli zasobów.

🧩 Struktura JOB-a JCL

Każdy job składa się z sekcji rozpoczynających się od operatora "//". Najważniejsze to:

  • // JOB — definicja zadania (nazwa, parametry użytkownika, priorytet)
  • // EXEC — wykonanie programu lub procedury
  • // DD — definicja danych (Dataset Definition) — pliki wejściowe/wyjściowe
// Przykład prostego JOB-a
//MYJOB JOB (ACCT),'DESC',CLASS=A,MSGCLASS=X
//STEP1 EXEC PGM=IEFBR14
//DD1 DD DSN=MY.DATASET.NAME,DISP=(NEW,CATLG),
            SPACE=(TRK,(1,1)),DCB=(RECFM=FB,LRECL=80)

🧾 Podstawowe elementy JCL

Kluczowe instrukcje i ich znaczenie

🏷️ JOB — Definicja zadania

Instrukcja rozpoczynająca każdy job. Określa parametry globalne.

//NAZWA_JOB JOB (numer_konta),'OPIS',
               CLASS=A,MSGCLASS=X,NOTIFY=&SYSUID

Najważniejsze parametry:

  • CLASS — klasa joba (wpływa na priorytet i alokację zasobów)
  • MSGCLASS — klasa wydruku komunikatów
  • NOTIFY — użytkownik do powiadomienia po zakończeniu
  • &SYSUID — zmienna systemowa = ID aktualnego użytkownika

▶️ EXEC — Wykonanie kroku

Uruchamia program lub procedurę w ramach joba.

//KROK1 EXEC PGM=IEBGENER
//KROK2 EXEC PROC=MOJA_PROCEDURA

PGM — nazwa programu (np. IEFBR14, SORT, IEBGENER)
PROC — nazwa procedury JCL (może zawierać wiele kroków)

💾 DD — Definicja zbioru danych

Określa dane wejściowe/wyjściowe dla kroku.

//WEJSCIE DD DSN=PLIK.WEJSCIOWY,DISP=SHR
//WYJSCIE DD DSN=PLIK.WYJSCIOWY,
              DISP=(NEW,CATLG,DELETE),
              SPACE=(CYL,(5,2)),
              DCB=(RECFM=FB,LRECL=80,BLKSIZE=800)

Najważniejsze parametry DD:

  • DSN — nazwa datasetu
  • DISP — dyspozycja (np. SHR, NEW, OLD, MOD)
  • SPACE — alokacja miejsca
  • DCB — charakterystyka bloku danych (format rekordu, długość itp.)

🔄 Zmienne w JCL i ARC

Jak używać symboli i makr do elastycznej konfiguracji

🔠 Symbole JCL (Symbolic Parameters)

Zmienne w JCL definiuje się za pomocą // SET lub jako parametry procedur.

// SET ENV=PROD
// SET DATA='20240501'
//STEP1 EXEC PGM=MYPGM
//INPUT DD DSN=MY.&ENV..DATA.&DATA,DISP=SHR

Powyższy przykład po podstawieniu staje się:
//INPUT DD DSN=MY.PROD.DATA.20240501,DISP=SHR

✅ Reguły nazewnictwa

- Nazwy zaczynają się od litery
- Maksymalnie 8 znaków
- Używane z prefiksem & przy odwoływaniu się
- Wartości w cudzysłowach jeśli zawierają spacje lub specjalne znaki

🔧 Zmienne ARC

ARC często wprowadza własne zmienne systemowe lub umożliwia definiowanie zmiennych środowiskowych dla lepszego zarządzania zasobami.

// SET &ARC_POOL='HIGH_PERFORMANCE'
// SET &ARC_TIMEOUT=3600
//*
//* Użycie w komentarzu lub przekazanie do programu przez PARM
//STEP1 EXEC PGM=ARCCTRL,PARM='POOL=&ARC_POOL,TIMEOUT=&ARC_TIMEOUT'

⚠️ Uwaga

Dokładna składnia i dostępne zmienne zależą od implementacji ARC w danym środowisku. Zawsze sprawdź dokumentację lokalną!

📦 Zmienne systemowe (predefiniowane)

JCL oferuje wbudowane symbole systemowe:

Zmienna Opis
&SYSUID ID aktualnego użytkownika
&SYSNAME Nazwa systemu
&SYSDATE Data w formacie YYDDD (rok/dzień roku)
&SYSTIME Czas w formacie HHMMSS
//OUTPUT DD DSN=LOG.&SYSUID..&SYSDATE..&SYSTIME,DISP=(NEW,CATLG)

⚙️ Konfiguracja z użyciem zmiennych

Jak tworzyć elastyczne i wielokrotnie używalne joby

📄 Procedury z parametrami

Procedury pozwalają na ponowne użycie kodu JCL. Parametry są przekazywane jak zmienne.

// Definicja procedury (np. w bibliotece PROCLIB)
//MYPROC PROC ENV=TEST,OWNER=&SYSUID
//STEP1 EXEC PGM=IEFBR14
//DD1 DD DSN=DATA.&ENV..&OWNER,DISP=(NEW,CATLG),
            SPACE=(TRK,1)
// PEND

// Użycie procedury w jobie
//JOB1 JOB ...
//RUN EXEC MYPROC,ENV=PROD,OWNER=OPERATOR

🔁 Dynamiczna konfiguracja w ARC

W środowisku ARC często można przekazywać zmienne kontrolujące np. limity zasobów, profile wydajnościowe czy ścieżki logowania.

// SET &MAX_CPU=300
// SET &LOG_LEVEL=DEBUG
// SET &POOL_NAME='ARC_BATCH_LOW'

//STEP1 EXEC PGM=ARCRUN,PARM=('MAXCPU=&MAX_CPU','LOG=&LOG_LEVEL')
//CTL DD *
POOL=&POOL_NAME
TIMEOUT=3600
/*

💡 Porada

Używaj zmiennych do oddzielenia logiki od konfiguracji — ułatwia to testowanie, migrację między środowiskami (DEV/TEST/PROD) i utrzymanie kodu.

🗂️ Konfiguracja zbiorów danych

Zmienne idealnie nadają się do konstruowania nazw datasetów w zależności od środowiska, daty, użytkownika itp.

// SET &CLIENT='ABC'
// SET &DATE='202405'
// SET &ENV='PROD'

//INPUT DD DSN=CLIENT.&CLIENT..SOURCE.&DATE,DISP=SHR
//OUTPUT DD DSN=CLIENT.&CLIENT..ARCHIVE.&ENV..&DATE,DISP=(NEW,CATLG),
            SPACE=(CYL,(10,5))

Wynik: CLIENT.ABC.ARCHIVE.PROD.202405

🏆 Best Practices

Zalecenia i pułapki do uniknięcia

✅ Nadawaj znaczące nazwy

Używaj nazw zmiennych, które mówią, co reprezentują: &ENV, &CLIENT_ID, &MAX_RECORDS.

✅ Używaj domyślnych wartości

Definiuj wartości domyślne w procedurach, aby job działał nawet bez przekazania parametrów.

✅ Dokumentuj zmienne

Umieszczaj komentarze wyjaśniające przeznaczenie każdej zmiennej i dopuszczalne wartości.

❌ Unikaj hardcoded wartości

Nigdy nie wpisuj na stałe nazw datasetów, ścieżek czy limitów — używaj zmiennych!

❌ Nie przekraczaj limitu 8 znaków

Nazwy symboli JCL są ograniczone do 8 znaków — planuj nazewnictwo odpowiednio.

⚠️ Testuj podstawienia

Zawsze sprawdzaj, jak job wygląda po podstawieniu zmiennych (można użyć JCL checker lub emulatora).

🎯 Kluczowe wnioski

  1. JCL to język sterowania zadaniami w środowisku mainframe IBM.
  2. ARC to często warstwa zarządzania zasobami rozszerzająca możliwości JCL.
  3. Zmienne (symbole) definiuje się przez // SET i używa z prefiksem &.
  4. Procedury pozwalają na wielokrotne użycie kodu i przyjmują parametry jak zmienne.
  5. Zmienne systemowe jak &SYSUID, &SYSDATE są predefiniowane.
  6. Best practices: używaj znaczących nazw, domyślnych wartości, unikaj hardcoded wartości.

🚀 Wskazówka

Zacznij od małego — przekształć jeden istniejący job, zastępując powtarzające się wartości zmiennymi. Potem twórz procedury. Zobaczysz, jak bardzo uprości to Twoją pracę!
