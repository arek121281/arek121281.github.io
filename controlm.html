🔍 Czym jest Control-M?

Enterprise Workload Automation — orkiestracja zadań w skali korporacyjnej

📋 Definicja

Control-M (BMC Software) to wiodąca platforma Workload Automation (WLA) służąca do harmonogramowania, orkiestracji, monitorowania i zarządzania zadaniami batch oraz procesami biznesowymi w środowiskach heterogenicznych — mainframe, distributed, cloud.

💡 Po co Control-M?

Nowoczesne organizacje uruchamiają tysiące jobów dziennie z zależnościami, harmonogramami, warunkami, alertami. Control-M automatyzuje to wszystko — zamiast ręcznego submisji JCL czy crontabów.

🔗 Warunki (Conditions) — IN/OUT

Łańcuchowanie jobów i zależności

🔗 Jak działają warunki

// Job A generuje warunek OUT po zakończeniu // Job B czeka na ten warunek jako IN JOB-A: OUT Condition: JOB-A-OK (dodawane gdy RC=0) JOB-B: IN Condition: JOB-A-OK (czeka aż pojawi się) IN Condition: FILE-READY (czeka też na plik) // Job B uruchomi się DOPIERO gdy OBA warunki spełnione // Wariant z datą ODAT: IN Condition: JOB-A-OK ODAT ODAT // ta sama data IN Condition: JOB-A-OK ODAT PREV // poprzedni dzień // AND/OR logic: AND (domyślnie) — wszystkie warunki muszą być spełnione OR — wystarczy jeden warunek

💡 Warunki vs Zależności (Dependencies)

Conditions to stringi (nazwy) umieszczane w globalnej tablicy. Flow Dependencies (w GUI) to uproszczony widok — za kulisami generują conditions. Conditions mogą być cross-folder i cross-server!

🔒 Zasoby (Resources)

Kontrola współbieżności i wzajemnych wykluczeń

🔒 Typy zasobów

🔢 Quantitative Resource

Zasób z liczbą dostępnych jednostek. Job rezerwuje N jednostek — gdy brak wolnych, czeka.

Resource: DB-CONNECTIONS
Max: 10
Job requests: 2 → 8 remaining

🚫 Control Resource (Mutex)

Wzajemne wykluczenie — Shared (wiele naraz) lub Exclusive (tylko jeden).

Resource: TAPE-DRIVE
Type: Exclusive
→ tylko 1 job naraz

🔔 Alerty i akcje (ON/DO)

Reakcje na zdarzenia — co robić gdy job się zakończy

⚡ Mechanizm ON/DO

// ON (warunek) → DO (akcja) ON stmt: NOTOK // Gdy job się nie powiedzie DO Shout // Wyślij alert Dest: ops-team@company.com Msg: "Job %%JOBNAME FAILED RC=%%COMPSTAT" DO Rerun // Ponów uruchomienie ON stmt: COMP CODE > 4 // Gdy return code > 4 DO Mail // Wyślij email To: dev-lead@company.com Subject:"Job %%JOBNAME RC=%%COMPSTAT" DO Set Variable // Ustaw zmienną Name: %%JOB_STATUS Value: FAILED ON stmt: OK // Gdy job OK DO Add Condition // Dodaj warunek Name: STEP1-DONE Date: ODAT // Inne ON statementy: ON DO NOT START (job nie wystartował w oknie) ON LATE (job się spóźnia vs SLA) ON LONG (job trwa dłużej niż zwykle)

❓ FAQ

Co to New Day Processing?▼
New Day Processing to codzienny proces (zwykle o północy lub w konfigurowalnej godzinie), w którym Control-M/Server: 1) czyści warunki z poprzedniego dnia, 2) ładuje definicje jobów do Active Jobs File (AJF) na nowy dzień, 3) sprawdza kryteria schedulingowe, 4) ustawia ODAT. To „serce" cyklu dziennego Control-M.
Czym różni się ODAT od daty systemowej?▼
ODAT (Order Date) to data planowania — „na kiedy" job jest zaplanowany. Nie musi być równa dacie systemowej. Np. job zaplanowany na ODAT=0115 może fizycznie wykonać się 16 stycznia o 2:00 w nocy (następnego dnia kalendarzowego), ale logicznie należy do dnia 15 stycznia. ODAT jest kluczem w warunkach i zasobach.
Jak działa AutoEdit (%%zmienne)?▼
AutoEdit to zmienne rozwijane w runtime. Predefiniowane: %%ODAT, %%JOBNAME, %%COMPSTAT, %%ORDERID, %%$DATE, %%OYEAR, %%OMONTH, %%ODAY. Własne: %%MYVAR — definiowane na poziomie joba, folderu lub globalnie. Używane w CMDLINE, ścieżkach, warunkach.
Jak obsługiwać ABEND / RC≠0?▼
Przez mechanizm ON/DO: ON COMP CODE > 0 DO Shout + DO Rerun. Można definiować: retry z interwałem, eskalację do innego zespołu, automatyczny ticket w ServiceNow/Remedy, warunkowe pomijanie (Set to OK jeśli RC=4), uruchomienie joba awaryjnego (DO Run Job). W BIM (Batch Impact Manager) można śledzić wpływ awarii na SLA.
Czym jest Jobs-as-Code?▼
Jobs-as-Code to podejście, w którym definicje jobów są zapisane w JSON (lub Python/Go templates) i zarządzane w Git. Control-M Automation API pozwala na: ctm build (walidacja), ctm deploy (wdrożenie). Integracja z Jenkins/GitHub Actions → pełne CI/CD dla jobów batch.
