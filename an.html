🔍 Przegląd — dwa narzędzia, jeden cel

Modernizacja mainframe bez ryzyka przepisywania kodu

🔄 Automate NOW Workload

Automate NOW (BMC Helix / Broadcom) to platforma Workload Automation (WLA) nowej generacji, zastępująca tradycyjne schedulery mainframe (CA-7, Control-M, TWS). Zarządza harmonogramowaniem i orkiestracją zadań batch i realtime — zarówno na mainframe, jak i w chmurze.

💡 Po co?

Zastąpienie starych schedulerów z/OS nowoczesnym narzędziem, które działa cross-platform: mainframe + Linux + cloud + kontenerach.

🌧️ Raincode Compiler

Raincode to rodzina kompilatorów, która kompiluje istniejący kod COBOL, PL/I i JCL do natywnego kodu .NET (CLR), umożliwiając uruchomienie aplikacji mainframe na Windows, Linux, Azure, AWS — bez przepisywania ani jednej linii kodu źródłowego.

🔥 Kluczowa idea

Replatforming, nie rewriting! Raincode kompiluje Twój COBOL tak jak IGYCRCTL, ale target to .NET zamiast S/390 machine code.

🔄 Automate NOW — Workload Automation

Nowoczesny scheduler zastępujący mainframowe joby

📋 Co to Workload Automation?

Workload Automation (WLA) to orkiestracja i harmonogramowanie zadań — batch jobów, procesów ETL, transferów plików, skryptów — w odpowiedniej kolejności, z zależnościami i monitoringiem. Na mainframe tę rolę pełniły CA-7, TWS (Tivoli), Control-M. Automate NOW to ich nowoczesny odpowiednik.

🌧️ Raincode — Kompilatory Mainframe dla .NET

Kompiluj COBOL, PL/I i JCL na platformę .NET — bez zmian w kodzie

🎯 Czym jest Raincode?

Raincode to belgijska firma oferująca kompilatory, które potrafią skompilować natywny mainframowy kod źródłowy (COBOL, PL/I, Assembler, JCL) do kodu wykonywalnego na platformie .NET / .NET Core. Oznacza to, że aplikacje mainframe mogą działać na Windows Server, Linux lub w chmurze (Azure, AWS) — bez przepisywania kodu.

✅ Kluczowa przewaga

Tradycyjna „modernizacja" mainframe = przepisanie milionów linii kodu (ryzyko, koszt, lata pracy). Raincode = rekompilacja — ten sam sprawdzony kod, nowa platforma. Czas migracji: miesiące zamiast lat.

📋 Szczegóły każdej fazy

🔍 Faza 1: Discovery — Inwentaryzacja▼
  • Skan wszystkich źródeł: COBOL, PL/I, ASM, JCL, copybooków
  • Identyfikacja zależności (CALL, COPY, EXEC SQL, EXEC CICS)
  • Mapowanie baz danych (DB2 tablice, IMS segmenty)
  • Inwentaryzacja VSAM datasetów, GDG, plików sekwencyjnych
  • Narzędzie: Raincode Discovery Tool / manualna analiza
📊 Faza 2: Assessment — Ocena złożoności▼
  • Ocena kompatybilności każdego programu z Raincode
  • Identyfikacja „problem areas": assembler inline, specyficzne CICS, IMS
  • Estymacja nakładu pracy (LOE — Level of Effort)
  • Raport: co migruje automatycznie (80-95%), co wymaga adaptacji (5-20%)
  • Plan migracji falistycznej (wave planning)
⚙️ Faza 3: Compile — Rekompilacja▼
  • Kompilacja COBOL/PL/I za pomocą Raincode Compiler → .NET assemblies
  • Konwersja JCL → Raincode JCL Interpreter skrypty
  • Konfiguracja runtime: VSAM emulacja, CICS runtime, code pages
  • Rozwiązywanie błędów kompilacji (zwykle 2-5% źródeł wymaga drobnych poprawek)
🗄️ Faza 4: Data Migration▼
  • DB2 → SQL Server / PostgreSQL (DDL + DML)
  • VSAM → pliki lokalne lub tablice SQL
  • EBCDIC → ASCII konwersja danych
  • Packed Decimal (COMP-3) → natywne typy bazy
  • ETL tools: SSIS, Azure Data Factory, custom scripts
🧪 Faza 5: Testing — Testy porównawcze▼
  • Byte-for-byte comparison — porównanie wyników: mainframe vs Raincode
  • Testy regresyjne na pełnych danych produkcyjnych
  • Performance benchmarking
  • Testy CICS (jeśli online)
  • UAT z użytkownikami biznesowymi
🚀 Faza 6: Deployment▼
  • Wdrożenie na docelową infrastrukturę (Azure VMs, AWS EC2, on-prem)
  • Konfiguracja Automate NOW jako schedulera (zamiast JES2/CA-7)
  • Cutover plan — przełączenie z mainframe na nową platformę
  • Okres równoległy (parallel run) — oba systemy działają jednocześnie

❓ FAQ

Czy Raincode obsługuje 100% kodu COBOL z mainframe?▼
Raincode obsługuje 95-99% typowego kodu COBOL. Nieobsługiwane mogą być: inline Assembler macros, bardzo specyficzne rozszerzenia IBM, niektóre zaawansowane IMS DL/I patterns. Te 1-5% zwykle wymagają drobnych adaptacji — nie przepisywania od zera.
Co z wydajnością? Czy .NET jest wolniejszy niż mainframe?▼
Zależy od workloadu. Dla batch processing .NET na nowoczesnych serwerach x86 jest porównywalny lub szybszy niż mainframe per-transaction (choć mainframe wygrywa w I/O-intensive workloads i skalowalności). Kluczowa korzyść: koszt — MIPS mainframe to $1000-3000/MIPS/rok, chmura to ułamek tej kwoty.
Jak Automate NOW zastępuje CA-7 / TWS?▼
Automate NOW importuje definicje jobów z CA-7/TWS (konwertery), zachowuje łańcuchy zależności i harmonogramy. Oferuje modern web UI zamiast ISPF, REST API do automatyzacji, i natywną obsługę cross-platform (mainframe + cloud w jednym workflow).
Czy można migrować stopniowo (falami)?▼
Tak — i to jest zalecane! Migracja falista (wave-based): 1) najpierw mniej krytyczne systemy, 2) potem core systemy. Mainframe i nowa platforma mogą działać równolegle. Raincode/Automate NOW obsługują hybrydowe scenariusze, gdzie część jobów nadal działa na z/OS, a część na cloud.
Co z EBCDIC?▼
Raincode automatycznie zarządza konwersją EBCDIC ↔ ASCII. Dane w pamięci mogą być przetwarzane w EBCDIC (dla zachowania kompatybilności sortowania, COMP-3 itp.), a konwersja na ASCII/UTF-8 następuje przy I/O. Code page jest konfigurowalna per aplikację.
Jak debugować skompilowane programy COBOL na .NET?▼
Raincode generuje symbole debugowania (.pdb) mapujące .NET IL na oryginalny kod COBOL. Można debugować w Visual Studio — stawia breakpointy w kodzie COBOL, podgląda zmienne COBOL (PIC, COMP-3) w natywnym formacie. To ogromna przewaga nad debugowaniem na mainframe (XPEDITER/Debug Tool).
