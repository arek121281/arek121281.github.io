🔄 TRANSFORMER

Kompletny przewodnik po architekturze Transformer - fundamentzie nowoczesnego AI. Zrozum jak działają GPT, BERT, LLM.

🧠 Architecture 👀 Attention 🤖 LLM 📊 Deep Learning

Czym jest Transformer?

Architektura sieci neuronowej która zmieniła AI

⚡ Krótka Odpowiedź

Transformer to architektura sieci neuronowej (deep learning model), opublikowana w papierze "Attention is All You Need" (2017) przez Google Brain i University of Toronto. Zrewolucjonizowała przetwarzanie sekwencji tekstu.

Zamiast przetwarzać tekst słowo po słowie (jak RNN), Transformer patrzą na cały tekst naraz i rozumieją powiązania między słowami w całym kontekście. To jest key difference - self-attention mechanism.

✓ Gdzie są używane?

• GPT (OpenAI) — ChatGPT, GPT-4 = czysty Transformer
• BERT (Google) — Transformer dla rozumienia tekstu
• T5 (Google) — Transformer dla różnych NLP taskó
• Vision Transformers (ViT) — Transformers dla obrazów!
• Llama, Mistral, Claude — Wszystkie LLM to Transformery
• Casi wszystko w AI 2023+ — SOTA models to Transformery

⚠️ Ważne

Transformer to architektura (blueprint), nie konkretny model. Jak budynek - wiele domów może mieć podobną architekturę ale różne detale, meble, wielkość. GPT, BERT, Llama - to wszystkie "domy" zbudowane na "planie" Transformer.

Przed Transformerem

Jakie były problemy z poprzednimi modelami?

📊 RNN (Recurrent Neural Networks)

RNN/LSTM były standardem przed 2017. Jak czytają sekwencję?

RNN Flow (Sekwencyjnie)
Input: "The cat sat on mat"
Krok 1: [The] → hidden_state_1
Krok 2: [cat] + hidden_state_1 → hidden_state_2
Krok 3: [sat] + hidden_state_2 → hidden_state_3
... i tak dalej, słowo po słowie

❌ Problemy RNN

• Sekwencyjne przetwarzanie - musi czekać na poprzedni krok (bardzo WOLNO)
• Vanishing gradients - nie pamięta długoterminowych zależności (tekst > 100 słów = problem)
• Nie parallelizuje - GPU nie może przyspieszyć (każdy krok czeka na poprzedni)
• Słabe na długi kontekst - zapomina co było 50 słów temu

🔍 Dlaczego Transformer Zwycięża?

Transformer Flow (Parallelnie)
Input: "The cat sat on mat"
CAŁY tekst w jednym time-step! → Attention
Każde słowo patrzą na WSZYSTKIE słowa jednocześnie
Parallelny proces = SZYBKO ⚡
  • ✓ Parallelizacja - wszystkie słowa naraz, GPU pełna moc
  • ✓ Długi kontekst - zmienna attention pozwala pamiętać (teoretycznie) nieskończony kontekst
  • ✓ Globalny kontekst - każde słowo wie o każdym innym słowie
  • ✓ Szybsze trenowanie - parallelne = szybciej (GPT-3 5 miesięcy zamiast lat)
  • ✓ Skaluje się lepiej - więcej danych, większy model = lepiej (RNN plateau)

🔢 Dimensionality (Rozmiary)

Transformer ma stałe rozmiary dla każdego wektora:

Rozmiary Wektorów (dla BERT)
Token embedding: 768 dimensions
Każde słowo = wektor liczb (768 liczb)
 
Multi-Head Attention: 12 heads
768 / 12 = 64 dims per head
 
Feed-Forward: 768 → 3072 → 768
(rozszerza się wewnątrz, potem się zwęża)
 
Attention heads: 12
Encoder layers: 12
Total params: 110M (BERT-base)

💡 GPT-3 vs BERT

BERT-base: 12 layers, 768 dims, 110M parameters
GPT-3: 96 layers, 12288 dims, 175B parameters (!)
To samo architecture, ale GIGANTYCZNE scale = GIGANTYCZNE moce

⚡ Self-Attention Mechanism

Serce transformera - jak model zrozumie powiązania między słowami

👀 Co to jest Attention?

Attention to mechanizm który pozwala modelowi skoncentrować się na "ważnych" słowach.

✓ Intuicja (Human Example)

Czytasz: "The cat sat on the mat. It was black."
Pytanie: Co było czarne? (what does "It" refer to?)
Twój "attention" skoncentruje się na "cat" - bo to jest kontekst.
Attention weights: cat=0.9, sat=0.05, mat=0.03, rest=0.02

Transformer robi dokładnie to samo, ale matematycznie!

🧮 Attention Formula (Scaled Dot-Product)

Attention(Q, K, V) = softmax( QKT / √dk ) V

Gdzie:

  • Q (Query) - co szukamy? (bieżące słowo pytaniem)
  • K (Key) - gdzie szukać? (indeksy w tekście)
  • V (Value) - jaka jest wartość? (zawartość słów)
  • dk - wymiar keya (64 dla 12-head attention)
  • QKT - similarity scores (jak podobne są query do każdego keya)
  • softmax - normalizuj do prawdopodobieństw (sum=1)
  • V - ważona suma wartości (weighted average)
# Attention w pseudokodzie
def attention(query, key, value):
    # Krok 1: similarity scores
    scores = query @ key.T # matrix multiplication
    scores = scores / math.sqrt(d_k) # scale

    # Krok 2: softmax (convert to probabilities)
    weights = softmax(scores) # range 0-1, sum=1

    # Krok 3: weighted sum of values
    output = weights @ value # weighted average

    return output

🎯 Self-Attention - Co Się Dzieje Krok po Kroku?

Attention Flow dla Słowa "cat"
Sentence: "The cat sat on the mat"
 
KROK 1: "cat" → Query (szukaj tego)
 
KROK 2: Score każde słowo (podobieństwo do query)
The: 0.1 (mało związane)
cat: 0.9 (sam siebie!)
sat: 0.7 (co robiła kota?)
on: 0.3 (mniej)
mat: 0.6 (gdzie siedziała)
 
KROK 3: Softmax (normalizuj)
cat: 0.35 (highest!)
sat: 0.25
mat: 0.20
The: 0.10
on: 0.10
 
KROK 4: Weź weighted average (0.35*cat_vector + 0.25*sat_vector + ...)
Output: nowa reprezentacja "cat" z kontekstem!

🔀 Multi-Head Attention

Jeden attention head = jeden typ relacji. Multi-head = wiele aspektów jednocześnie:

12-Head Attention (BERT)
Head 1: Syntactic relations (podział i czasowniki)
Head 2: Co robi (verb-object relations)
Head 3: Singular/Plural (gender, number agreement)
Head 4: Location (gdzie, kiedy)
... (8 more heads)
 
Concat all 12 outputs → 768D vector

Każdy head uczy się innych "pojęć" - razem tworzą pełne rozumienie tekstu!

🔧 Komponenty Transformera

Budulce architektury

🏷️

Token Embedding

Konwersja słów na wektory.

  • Vocab size ≈ 50K słów
  • Każde słowo = wektor 768D
  • Learned representation
  • Special tokens: [CLS], [SEP], [MASK]
📍

Positional Encoding

Mówi modelowi gdzie są słowa (nie ma sensu porządku bez pozycji).

  • Sinusoidal functions (sin/cos)
  • Dodane do embedding
  • Relative position info
  • Supports long sequences
👀

Self-Attention

Jądro transformera - relacje między słowami.

  • Query, Key, Value matrices
  • Softmax normalization
  • Attention weights (visualizable!)
  • O(n²) complexity
🎯

Multi-Head Attention

Wiele attention heads dla różnych aspektów.

  • Parallel attention operations
  • h heads (usually 8-16)
  • d_k = d_model / h
  • Concatenate & project
🧠

Feed-Forward Network

Po attention - dodatkowa transformacja wiedzy.

  • Dense layer 1: expand
  • ReLU activation
  • Dense layer 2: shrink back
  • Pointwise (per position)
⚙️

Layer Normalization

Stabilizuje trenowanie, normalizuje wartości.

  • After attention & FF
  • Learnable scale & shift
  • Helps gradient flow
  • Pre-norm vs Post-norm

📐 Matematyka Transformera

Dokładne wzory (dla ciekawych)

🔢 Multi-Head Self-Attention (Dokładnie)

Attention(Q, K, V) = softmax(QKT/√dk) V
MultiHead(Q, K, V) = Concat(head1,...,headh)WO
gdzie headi = Attention(QWiQ, KWiK, VWiV)

Interpretation:

  • Każdy head ma własne Q, K, V transformacje (W matrices)
  • Attention dzieje się osobno w każdym head
  • Wyniki konkatenowane i mnożone przez WO (output projection)
  • Powraca do d_model wymiarów

📊 Feed-Forward Network

FFN(x) = max(0, xW1 + b1)W2 + b2

Gdzie:

  • W1: d_model → d_ff (zwykle 4*d_model)
  • max(0, ...): ReLU activation
  • W2: d_ff → d_model (powrót)
  • Applied per position (independent)

💡 Dlaczego d_ff = 4*d_model?

Dla BERT (d_model=768): d_ff = 3072 = 4×768
Empirycznie znaleziono że ta proporcja działa dobrze.
FFN jest gęstą "knowledge storage" warstwą.

🌊 Softmax Formula

softmax(xi) = exi / Σj exj

Co to robi:

  • Konwersja dowolnych liczb na prawdopodobieństwa (0-1)
  • Suma zawsze = 1
  • ex emphasizes największe wartości
  • Perfect dla attention weights!

🎯 Positional Encoding (Sinusoidal)

PE(pos, 2i) = sin(pos / 100002i/d_model)
PE(pos, 2i+1) = cos(pos / 100002i/d_model)

Czemu sinusoidy?

  • Periodic patterns - model nauczy się relative positions
  • Wszędzie dostępne - dla każdej pozycji
  • Extrapolate - model może obsłużyć sekwencje długsze niż trenowanie
  • Nie uczony - fixed, nie zużywa parametrów

📐 Layer Normalization

LayerNorm(x) = γ * (x - mean(x)) / sqrt(var(x) + ε) + β

Gdzie:

  • Normalizuj każdy sample (nie batch)
  • γ, β - learned scale and shift (optional)
  • ε - small number (avoid division by zero)
  • Stabilizuje gradient flow podczas backprop

🎓 Jak Transformers Się Trenują?

Od danych do działającego modelu

📚 Pre-training (Ogromne skale)

LLMy są trenowane w dwóch fazach:

FAZA 1: Pre-training (Unsupervised)
Data: 300B+ tokens (Common Crawl, Books, Wikipedia)
Task: Next Token Prediction (LM)
 
Input: "The quick brown fox"
Predict: "jumps" (next token)
 
Loss: Cross-entropy (how wrong was prediction)
Optimizer: Adam (adaptive learning rates)
 
Duration: weeks-months (GPT-3 took 5 months!)
Compute: MASSIVE (1000s of GPUs)

🎯 Fine-tuning (Transfer Learning)

FAZA 2: Fine-tuning (Supervised)
Start: Pre-trained model (GPT-3)
Data: Task-specific (1K-10K examples)
 
Example: Classification
Input: "I loved this movie!"
Output: Sentiment = Positive
 
Loss: Task-specific (cross-entropy, MSE, etc)
Learning rate: Much smaller (don't break pre-training!)
 
Duration: hours-days (GPU friendly!)
Cost: Cheap (<$100 vs millions for pre-train)

✓ Transfer Learning Power

Pre-trained model już "zna" język, gramatykę, pojęcia. Fine-tuning just adapts this knowledge. To jest dlaczego można trenować na małych datasetach!

🔄 RLHF (Reinforcement Learning from Human Feedback)

Dla ChatGPT-like modeli:

FAZA 3: RLHF (dla conversational models)
1. SFT (Supervised Fine-Tune)
  Fine-tune na high-quality prompts + responses
 
2. Reward Model Training
  Ludzie oceniają: "which response is better?"
  Train model to predict preference
 
3. PPO (Proximal Policy Optimization)
  Generator model updated using reward signal
  Maximize: quality of responses
  Minimize: divergence from SFT model

⚠️ RLHF Challenges

• Reward hacking - model optimizes for metric, not actual quality
• Alignment problem - how to encode human values?
• Expensive - need human raters (thousands of evaluations)
• Somewhat alignment-theater (doesn't solve all problems)

🔀 Warianty & Optymizacje

Ulepszenia do standardowego transformera

⚡ Efficient Transformers

Problem: Standard attention = O(n²) complexity. Dla 2000 słów = 4M operacji!

  • Sparse Attention — attention tylko na subset słów (nie wszyscy)
  • Linformer — linear complexity (O(n)) zamiast O(n²)
  • Performer — kernel methods, faster attention
  • FlashAttention — optimized CUDA kernels (GPU-friendly)
  • Local Attention — attention tylko na sąsiednie słowa (sliding window)

📏 Encoder vs Decoder vs Causal

Type Attention Mask Input/Output Przykład
Encoder-only Bidirectional Tekst → Representation BERT, RoBERTa (classification)
Decoder-only Causal (future masked) Tekst → Next tokens GPT, Llama, Mistral (generation)
Encoder-Decoder Both Tekst → Tekst T5, BART (translation)

🔧 Innowacyjne Warianty

  • Rotary Position Embeddings (RoPE) — lepsze pozycyjne encoding (LLaMA używa)
  • ALiBi — Attention with Linear Biases (prostsze niż sinusoidal)
  • GQA (Grouped Query Attention) — mniej KV heads dla szybkości
  • Mixture of Experts (MoE) — conditional FFN (dense to sparse)
  • Cross-layer Attention — skip connections między dalekimi layerami
  • Adapter Layers — mały tuning bez pełnego fine-tuning

🎯 Scaling Laws (Co się Stało w 2020-2024)

Chinchilla, PaLM, GPT-3.5 papers odkryły:

  • Bigger models = better (smoothly improving)
  • Model size ≈ Data size (Chinchilla scaling laws)
  • Grok'ing effect - plausible deniability does not work; sudden jumps in capability
  • Emergent abilities - at certain scale, model magically gains new skills!
  • Chain of Thought - bigger models exhibit reasoning (surprising!)

✓ Trend

GPT-3 (175B) → GPT-4 (?B, rumored ~1T) → future = gigantic models
Trend: Bigger, faster, smarter = unstoppable
